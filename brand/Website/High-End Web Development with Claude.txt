## PART 4 — Conflitos & Divergências

A análise técnica das 41 fontes revelou quatro grandes conflitos metodológicos e arquiteturais entre tutoriais de influenciadores e a documentação oficial/análise de engenharia sênior.

| Conflito / Divergência | Posição da Fonte A | Posição da Fonte B | Recomendação Fundamentada do Arquiteto |
| :--- | :--- | :--- | :--- |
| **1. Geradores de Browser ("Vibe Coders") vs. IDEs Locais / CLI de Terminal** | Criadores de conteúdo (Ras Mic, Samuel Rondo, Jono Catliff) defendem criar projetos inteiros em geradores de browser (v0, Bolt.new, Lovable, Claude Design) com prompts únicos. | Desenvolvedores Seniores no Reddit e Hacker News afirmam que geradores de browser criam código acoplado, inflado e inmanutenível quando o projeto passa de um protótipo [542, 827, 1228–1233]. | **Adotar Pipeline Híbrido em Estágios**. Utilize geradores baseados em browser (como Vercel v0) exclusivamente no início para explorar a interface visual dos componentes. Em seguida, exporte o código React/Tailwind limpo para uma estrutura local Next.js gerenciada via Claude Code ou Cursor AI. |
| **2. "One-Shot Prompting" em 20 Minutos vs. Loop Iterativo Exploração-Plano-Código-Verificação** | Vídeos do YouTube afirmam que sites complexos de "\$10.000 a \$50.000" são construídos com um único prompt em sessões de 20 minutos. | Documentação da Anthropic e análises de engenharia provam que um prompt único satura a janela de contexto com suposições não verificadas, gerando degradação e o erro do "código quase certo". | **Executar o Loop de 4 Fases Obrigatório**. Proíba o "one-shot". Execute sequencialmente: 1. *Explorar* (Plan Mode), 2. *Planejar* (`SPEC.md`), 3. *Implementar*, 4. *Verificar* (Testes e Puppeteer) [120–122, 256]. Use `/clear` frequentemente entre subtarefas. |
| **3. Raspagem Bruta / Clonagem de Sites vs. Extração Limpa de Design System** | Tutoriais de clonagem recomendam baixar o HTML/CSS/JS bruto de sites com extensões do Chrome e injetá-los no Claude para clonar interfaces [280–281]. | Documentação da Anthropic, Meng To e comunidades de desenvolvimento alertam que clonar código raspado cria código engessado e inmanutenível; a regra é extrair apenas regras de estilo e design tokens [128–130, 554, 962–963, 1201]. | **Extraia Tokens (`DESIGN.md`), Não Código Bruto**. Utilize ferramentas como `Open Design` ou `Firecrawl MCP` para extrair apenas paleta de cores, tipografia e espaçamentos para o arquivo `/DESIGN.md`. Reconstrua o layout do zero usando componentes Shadcn UI e Next.js limpos. |
| **4. Modo Automático Sem Supervisão ("Auto Mode") vs. Controle Estrito de Permissões** | Vídeos recomendam ativar o modo automático sem checagens ("dangerous skip permissions") para que o agente rode de forma ininterrupta. | Documentação da Anthropic e pesquisas de segurança alertam que execuções sem travas causam consumo infinito de tokens, fugas de sandbox e vulnerabilidades de *HalluSquatting*. | **Uso de Sandboxing Isolado com Travas de Segurança (Hooks)**. Ative o modo automático exclusivamente em ambientes isolados no nível de sistema operacional (`/sandbox`) [131–132]. Implemente um script *Stop hook* (`.claude/hooks/stop.sh`) que impede a conclusão do turno até que os testes passem. Requeira aprovação manual para pushes no git e deployments. |
